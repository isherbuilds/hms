# Spec: Core-screen refinement

Status: ready
Authority: 2026-08-24 brainstorm decisions and the 2026-08-24 user revision; evidence in `docs/research/opd-ipd-reference-flows.md` and the **Core-screen UX** row in `docs/research/README.md`
Supersedes: only the patients-page URL `q` outcome in Slice 4 of `docs/specs/midday-adoption.md`; only the `includeClosed` half of that spec's deferred “OPD list `q`/`includeClosed` URL state” item; and the older separate **New walk-in**/**Book appointment** day actions and **Now/Later** intake contract in `docs/specs/opd.md` and `docs/specs/opd-desk-lifecycle.md`. OPD search text stays client-local.

## Problem

Reception uses the right core records, but the main desk screens still create avoidable risk and effort.

The intake loses an unfinished draft without a warning. Its separate timing paths hide patient search and can turn a permission block into a different appointment type. Keyboard focus stops between steps. Disabled actions do not explain what is missing. Errors can appear far from the section that needs attention. Long patient results can also push the intake beyond a narrow viewport. A configured attendance fee is also treated as mandatory, so reception cannot record a procedure-only or packaged case without charging it.

Patient records hold both age and date of birth. Those values can disagree. Patient edits can silently overwrite a newer edit from another terminal. Phone formatting can hide duplicates. The patient picker can also classify a formatted phone as a name. Sex silently defaults to a value that the operator did not choose.

List state is inconsistent. The OPD closed-row filter disappears on reload, but search text should remain temporary. The patients page puts search text in the URL, which conflicts with that policy. OPD day rows also need a complete keyboard path.

## Solution

Refine the current screens without changing the care model.

Navigate successful intake directly to the created OPD record's Clinical tab, where the patient slip is immediately available; Billing remains an adjacent record tab. (This sentence formerly sent paid walk-ins to Billing, which contradicted decision D-a, `docs/specs/opd.md`, and `docs/specs/opd-desk-lifecycle.md`; D-a stands.) Use one **New appointment** day action and one `/opd/new` intake; do not repeat it on the dashboard. Put one autofocused patient combobox first. The intake uses that one control to find or register a Patient; it does not duplicate caller name and phone fields below it. Existing caller-only scheduled records remain supported at check-in, but this intake always links a Patient before booking.

Show one compact **When** control with **Now** and **Later**. **Now** uses `opd.createWalkIn` without a client time claim; the server stamps the fresh arrival instant. **Later** reveals **Date and time · <timezone>** and uses `opd.book`, whose server boundary accepts only a future minute. Keep the same optional Services picker in both modes. Search the catalog on the server and return at most six rows. Selected service rate, tax, amount, subtotal, and total are calculated first on the client from local form state, using the shared invoice-math module, so adding, changing, or removing a service updates the preview synchronously without waiting for a care team or quote. Later booking snapshots selected services as dormant pending Charges. Once the required patient and care-team identifiers exist, Now fetches the server-authoritative quote and may create a valid zero-value walk-in without a financial document. See D017.

Store one birth date and one estimate flag. An entered age becomes an estimated date of birth. Every age display derives from that date and prefixes estimates with `~`. Require an explicit sex choice.

Protect dirty intake drafts with the existing discard-confirmation pattern. Make patient updates compare the loaded `updatedAt` value inside the organization scope. Reject stale writes with a clear refresh prompt. Normalize phone values to digits only for matching and classification. Keep the stored and displayed phone text unchanged.

Put `includeClosed` in validated OPD URL search state. Keep OPD search text and patients-page search text in client state. Preserve the patients-page debounce and `keepPreviousData` behavior.

Complete the keyboard path. Patient selection moves focus to Department. Enter advances or submits each intake step. Day rows accept focus and Enter. Required fields show markers. Disabled primary actions explain what is missing. Mutation errors stay in the section that owns the failed action. Keep patient search results inside the field and viewport at 400 px and wider.

The single OPD day list remains unchanged. Its statuses remain **Booked**, **Checked In**, **Cancelled**, and **No show**. Atomic walk-in settlement, inline registration, 10-second polling, and keyset pagination also remain unchanged.

## User Stories / Scenarios

1. As a front-desk operator, I finish a settled walk-in and press Enter to return to the OPD day, so I can continue desk work without choosing among secondary links.
2. As a front-desk operator, I start any OPD appointment in one autofocused patient search, choose or register a persisted Patient there, and then choose **Now** or **Later**. Now settles using server time; Later books the entered organization-local future minute.
3. As a front-desk operator, I enter a known age when the birth date is unknown, so the record keeps one estimated birth date and shows an honest `~` age.
4. As a front-desk operator, I leave and return to an OPD URL, so its closed-row filter returns while my temporary search text does not enter the URL.
5. As a front-desk operator, I try to leave a dirty intake draft, so the console asks before it discards my work.
6. As a front-desk operator, I save a patient record that another terminal changed, so the console rejects my stale edit and asks me to refresh instead of overwriting it.
7. As a front-desk operator, I search `98765 43210` after a record stored `98765-43210`, so duplicate matching treats both values as the same phone while preserving the stored display format.
8. As a front-desk operator, I use only the keyboard through intake and the day list, so focus and Enter follow the order of the task.
9. As a front-desk operator, I see a required marker and a local message when a required value is missing, so a disabled action never leaves me to guess.
10. As a front-desk operator, I search the patients page, so previous results stay visible during its debounced request and the search text stays off the URL.
11. As a front-desk operator, I register a patient, so I must choose sex and cannot save a silent default.
12. As a front-desk operator, I lose a mutation race during caller check-in, so the shared OPD conflict refresher reloads the winning **Booked**, **Checked In**, **Cancelled**, or **No show** state.
13. As a front-desk operator, I use patient search on a 400 px viewport, so long names, MRNs, phones, and ages do not create horizontal page overflow.
14. As a front-desk operator, I settle an immediate appointment, so a configured server-selected consultation or follow-up fee appears once in Services as an ordinary service line with the same row and remove control as other services. I cannot reprice it or select it from the picker. If no fee is configured, I see no consultation line.
15. As a front-desk operator without billing-write permission, I select **Now**, so the intake keeps my choice and explains why it cannot settle instead of silently scheduling.
16. As a front-desk operator, I may select services for a future appointment; they remain visible, persist with the booking, and stay out of cashier work until check-in.
17. As a front-desk operator, I select **Now**, so an old browser page cannot submit a stale arrival minute; the server supplies the time. I select **Later** only when I need to enter a future minute.
18. As a front-desk operator, I settle an immediate procedure-only or packaged case, so I can omit the configured attendance fee with no reason or invoice-note prefix while the server remains the authority for the quote, Charges, and invoice lines.

### Patient schema rollout, age conversion, and sex

- `packages/db/src/schema/patients.ts` ends with `patients.dateOfBirth` `NOT NULL` and `patients.dobEstimated` boolean `NOT NULL DEFAULT false`. It removes `patients.ageYears`, `patients_age_or_dob_check`, and `patients_age_range_check`.
- D007 makes this a two-deployment migration, not three migration files applied before one application deploy.
  - **Phase A — additive schema deployment:** change the intermediate schema to add nullable `dob_estimated`, keep `age_years` and nullable `date_of_birth`, and change `updated_at` to `timestamptz(3)`. The direct Drizzle owner is `packages/db/package.json`; generate the additive migration with `(cd packages/db && bun run db:generate -- --name=patient-dob-estimate-add)` and the custom data migration with `(cd packages/db && bun run db:generate -- --custom --name=patient-dob-backfill)`. The custom SQL derives `date_of_birth` for each age-only row from the migration's fixed calendar date, sets `dob_estimated = true` for those rows, and sets false for exact existing dates. The precision migration normalizes every existing `updated_at` through an explicit `timestamptz(3)` cast so no microsecond token survives.
  - Deploy Phase A through the shared pre-start migrator. Then deploy the dual-read/dual-write application. While old and new instances overlap, the new application reads either legacy `age_years` or the new date fields and writes both representations. Drain old instances before any destructive migration. The release owner must reconcile any age-only writes completed by draining old instances with the same idempotent backfill rule before Phase B. This reconciliation is a deployment boundary and a Phase B precondition, not an application fallback.
  - **Phase B — final model deployment:** only after the dual-compatible application is live, old instances have drained, and the reconciliation reports no null `date_of_birth`, change the schema to make `date_of_birth` and `dob_estimated` non-null and remove `age_years` and its checks. Generate the cleanup with `(cd packages/db && bun run db:generate -- --name=patient-dob-model-finalize)`. Deploy that generated migration through the shared pre-start migrator with the final application cutover.
- Drizzle owns the numeric prefixes, `packages/db/src/migrations/meta/_journal.json`, and snapshots. The stable suffixes are `patient-dob-estimate-add`, `patient-dob-backfill`, and `patient-dob-model-finalize`. Do not predict `0001`, `0002`, or `0003`. Do not edit generated SQL or generated metadata. Write only the custom backfill SQL.
- `packages/api/src/routers/patient.ts` removes `ageYears` from the final public `patientFields`. `patient.register` and `patient.update` accept `dateOfBirth: YYYY-MM-DD` and `dobEstimated: boolean`; the final model does not persist an age.
- `apps/web/src/lib/patient-age.ts` exports the pure helper `ageYearsToEstimatedDateOfBirth(ageYears: number, orgToday: string): string`. `orgToday` is the explicit organization-local `YYYY-MM-DD`; the helper never reads the machine clock. It subtracts calendar years. If that subtraction targets a non-leap year from February 29, it clamps to February 28. The file also exports `patientAgeYears(dateOfBirth: string, orgToday: string): number` and `patientAgeLabel(dateOfBirth: string, dobEstimated: boolean, orgToday: string): string`; the label prefixes an estimate with `~`.
- `apps/web/src/components/patient-form.tsx` consumes `ageYearsToEstimatedDateOfBirth`. An explicit date sends `{ dateOfBirth, dobEstimated: false }`. Age input sends the derived date and `{ dobEstimated: true }`. An explicit date wins if both controls have values.
- `apps/web/src/components/opd-patient-picker.tsx`, `apps/web/src/routes/$orgSlug/patients/index.tsx`, and `apps/web/src/routes/$orgSlug/patients/$patientId.tsx` derive every age from the date with the organization-local today.
- `patient-form.tsx` gives `sex` an empty initial value. Its label has a visible required marker. Submit blocks with **Choose sex**. No API or form default selects `male`, `female`, `other`, or `unknown`.

### Patient concurrency and honest conflicts

- `patients.updatedAt` ends as `timestamptz(3)`. `EditablePatient` in `patient-form.tsx` has `updatedAt: string`, and the patient route passes the loaded millisecond ISO string through `PatientSheet` to `PatientForm`.
- `patient.update` accepts `updatedAt: z.iso.datetime({ precision: 3 })`. It issues one organization-scoped `UPDATE` whose predicate compares `orgId`, `patientId`, and the loaded `updatedAt`. The same statement sets `updatedAt` to `greatest(statement_timestamp(), patients.updated_at + interval '1 millisecond')::timestamptz(3)` and returns the row. The explicit cast makes the returned token millisecond exact. The `+ 1 millisecond` floor gives two successful writes distinct tokens even when their statements start in the same millisecond.
- If that statement updates zero rows, the handler performs one second, organization-scoped existence read by `orgId` and `patientId`. An existing row returns `ORPCError("CONFLICT", { message: "This patient changed after you opened it.", data: { code: "STALE_RECORD" } })`; no scoped row returns `NOT_FOUND`. The mutation never retries.
- The existing fire-and-forget `patient.update` audit remains after the successful mutation, outside the database mutation. A stale or missing result returns before that audit call. Integration tests call the existing `drainAuditWrites()` seam before they assert that a success has one audit and stale or missing attempts have no success audit.
- A UID collision returns `ORPCError("CONFLICT", { message: "A patient with this UID already exists.", data: { code: "UID_TAKEN" } })` only when Postgres names `patients_org_uid_idx`. `packages/api/src/lib/db-errors.ts` exposes the violated constraint. Other conflicts keep the server message and do not receive the UID field message.
- `apps/web/src/lib/orpc-error.ts` adds `errorDataCode(error: unknown): string | undefined`. `applyOrpcFieldError` maps `UID_TAKEN` to `uid`. `STALE_RECORD` offers refresh. Accepting refresh invalidates `orpc.patient.get`; fresh data must arrive before the sheet resets or closes. It never retries the mutation.

### Phone matching and rendering

- Add the dependency-free helper `normalizePhone(value: string): string` in `packages/api/src/lib/phone.ts`. It returns `value.replace(/\D/g, "")`. The API router and picker import it through `@hms/api/lib/phone`.
- `patient.search` normalizes a phone lookup before it builds SQL. A phone lookup requires at least four normalized digits. A supplied value with fewer than four normalized digits fails with the router's validation error; a generic query with fewer digits skips the phone predicate. Neither path may compare a digits-only SQL expression with an empty string or empty pattern.
- `patient.search` is a directory projection, not a full Patient read. It returns only `id`, `mrn`, `name`, `phone`, `sex`, `dateOfBirth`, `ageYears`, and `createdAt`, the fields rendered by the patient registry and picker. Full clinical, contact and attribution fields stay behind `patient.get`.
- A valid phone lookup compares normalized input with a digits-only SQL expression over `patients.phone`. It never rewrites stored phone text.
- The picker classifies a value with at least four normalized digits and no letters as a phone. Any value with text is a name. A shorter digit-only value remains an incomplete query and cannot seed a phone.
- Every rendered phone in the OPD patient picker, patients list, and patient detail uses `font-mono tabular-nums`. Stored display format stays unchanged.

### Intake timing, services, state, keyboard behavior, and prototype handoff

- `apps/web/src/components/opd-intake-form.tsx` keeps no success-only state. A successful mutation clears dirty state and navigates directly to the created record's Clinical tab; Billing remains one adjacent tab where receipts are available (D-a).
- The OPD day has one action labelled **New appointment** with a plus icon. It opens one `/opd/new` intake. The route validates only optional `patientId` and `includeClosed`. **When** remains local form state and never enters route search.
- The intake page and meta title use **Appointment**. The dashboard queue has no duplicate creation action.
- `OpdPatientSearch` renders first and uses the native input autofocus attribute. It is the only patient-entry control in intake. Its controlled query has one state owner, the first typed character is retained and searched, and Base UI owns input-driven popup requests. A completed no-match can open registration with the entered phone or name as its seed; the appointment mutation still receives a persisted Patient id rather than loose caller text.
- The patient combobox popup uses the field width up to the available viewport width. It cannot make the page wider. Result rows give each text container `min-width: 0`. Long names, MRNs, phones, and ages wrap or truncate inside the row. The popup remains usable at a 400 px viewport.
- The intake shows one native **When** select. **Now** is the default; **Later** is the only alternative. There is no browser-clock comparison, polling interval, touched-time state, or automatic path inference.
- **Now** calls `opd.createWalkIn`, which accepts no `scheduledLocal`. The handler derives `now`, `scheduledFor`, `businessDate`, and arrival ordering from one fresh server instant.
- **Later** reveals one required `datetime-local` labelled **Date and time · <timezone>** and calls `opd.book` with `scheduledLocal: YYYY-MM-DDTHH:mm`. The server accepts only a value later than its fresh organization-local minute and owns the inline rejection message.
- Switching **When** never falls through to the other procedure. The same optional selected services remain visible in both modes. Only **Now** has a quote, consultation-fee omission, and settlement.
- An immediate appointment requires OPD create, patient read, and billing write. `opd.createWalkIn` declares `orgProcedure({ opd: ["create"], patient: ["read"], billing: ["write"] }, ...)`; this is the server authorization boundary, not only a UI gate. If the operator cannot settle, the intake keeps **Now** selected. Its adjacent inline message explains the billing-write requirement. Activation focuses **When** and runs no mutation. The client never changes the selection or falls back to `opd.book`.
- Services and their first financial preview do not depend on care-team selection. Each selected catalog result already carries its display rate and tax, so the client uses the shared invoice-math utility to render that service's amount plus subtotal, tax, and total synchronously. It does not wait for a query and does not duplicate arithmetic. Once patient, department, and practitioner are present under **Now**, `opd.quoteWalkIn` verifies all selected ids and adds the server-selected consultation/follow-up line. Creation still revalidates every client claim.
- An immediate selection shows Services and a server-authoritative quote. A non-zero quote opens settlement. A zero quote is valid and creates the checked-in appointment and token without an Invoice or Payment. The configured consultation/follow-up line stays server-owned and removable through `omitConsultFee`.
- **Later** has the same optional Services picker and synchronous service-only financial preview, but no consultation fee, omission, discount, or settlement. `opd.book` verifies and snapshots selected services as pending Charges in the appointment transaction. Cashier/dashboard unbilled totals ignore them until check-in.
- Care team copy does not claim that the section sets a fee. It tells the operator that a configured consultation or follow-up fee appears in **Services**.
- Enter has one owner. While the service search box contains a non-empty query, it owns Enter and selects the highlighted service. Only an empty service box lets the immediate intake advance. Department advances to Practitioner, Practitioner advances to **When**, a ready later intake calls `opd.book`, a ready immediate intake opens settlement, and ready settlement confirms. Enter in a multiline note never submits.
- The route-facing dirty value stays true when settlement or later booking fails. Successful walk-in and scheduled-booking mutations clear dirty immediately before direct record navigation. No other mutation result clears it.
- Required labels show visible markers. Mutation errors render in their owning section: patient errors in Patient, care-team or booking errors in Care team, time errors under Date and time, quote or service errors in Services, and settlement errors in settlement.
- The accepted D-h prototype behavior applies to intake primary actions. An unavailable intake primary may remain focusable with `aria-disabled="true"`. Its adjacent inline text names the first missing or invalid prerequisite. Pointer, Enter, or Space activation moves focus to that first invalid field and never runs the business action. Do not apply this focusable `aria-disabled` pattern to settlement unless settlement also supplies the same first-missing reason and focus target contract.
- `apps/web/src/components/opd-intake-services.tsx` lets the native number input hold a transient edit and clamps once on blur. Enter commits the same clamp and prevents implicit outer-form submission; the server remains the quantity enforcement boundary.
- `/opd/new` validates optional `patientId` and `includeClosed`. `patientId` preselects a patient. **New appointment** forwards both values when present. **Back** navigates to the OPD day with only `includeClosed` when true; it never forwards `patientId` or `q`. Local OPD search therefore clears.
- `apps/web/src/routes/$orgSlug/opd/new.tsx` uses the existing `useBlocker`, `useConfirm`, and `ConfirmDialog` pattern from `patient-sheet.tsx` for in-app navigation and browser unload.
- Production popups remain Base UI components behind `ClientOnly` under D008. Priced walk-ins keep the D015 atomic settlement. Zero walk-ins skip financial records. `opd.book` remains the scheduled path without settlement and persists only selected service Charge snapshots. No additional OPD state is introduced.

### Conditional attendance-fee omission

- `opd.quoteWalkIn` adds `omitConsultFee: z.boolean().optional()`, defaulting to false. `opd.createWalkIn` adds `settlement.omitConsultFee: z.boolean().optional()` with the same default. When the boolean is true, the server skips the selected consultation or follow-up line. No omission reason field exists, and no cross-field reason validation applies.
- Both procedures independently run the existing consultation or follow-up fee selection with `scope.orgId`; neither trusts a client item id, amount, quote line, or prior selection. `opd.quoteWalkIn` reselects on every request. `opd.createWalkIn` re-runs the care-team and fee selection with the transaction executor inside the existing D015 transaction. If omission is requested but no configured active fee exists, omission is a harmless no-op and the quote has no consultation line.
- The quote response is authoritative. A retained selected fee appears once in `lines` with `source: "consultation"`. An omitted fee does not appear in `lines`. Services and totals use only the returned response. No omission reason is returned.
- When an immediate quote has a configured fee, Services shows **Omit fee** on the ordinary server-selected service row, with the same remove control as other services. The action sends `omitConsultFee: true`; it has no reason field and does not delete or reprice the attendance-fee line optimistically. The client retains its omission choice if requoting fails.
- A successful omitted quote replaces the displayed fee and totals from the response. **Restore fee** clears the boolean and sends `omitConsultFee: false`. A future scheduled selection keeps Services but has no quote or omission control. The existing scheduled check-in path keeps its configured attendance fee.
- Inside the D015 transaction, a valid omission creates no `consult_fee` Charge. Therefore, `issueInvoiceTx` receives no attendance-fee Charge and creates no attendance-fee invoice line. Added service Charges, itemized billing, settlement, Payments, Receipts, journal entries, and transaction atomicity stay on the existing path. No second billing or procedure path is added.
- `packages/api/src/routers/billing.ts` owns the arithmetic and note-validation seam. `settlement.note` is the original server-trimmed operator note. It is validated for discount and unpaid-balance rules independently of fee omission. Omission supplies no reason and no server-owned invoice-note prefix.
- `issueInvoiceTx` reads pending Charges and calls `computeInvoiceLines` once to produce the authoritative subtotal, tax, and grand total. Before it allocates or inserts the invoice, it validates the original `settlementNote`: a positive discount requires a non-empty note, and, when collected payment amounts are defined, the helper requires a non-empty note when collected is below the computed grand total. Fee omission cannot satisfy either rule. The immutable note stores the existing settlement note without an omission prefix.
- The public `billing.issueInvoice` input remains `{ appointmentId; discountAmount; note? }`. Its handler passes the original note for existing validation and stores it unchanged. Other `issueInvoiceTx` callers must choose the same explicit settlement or non-settlement contract; there is no implicit empty collected amount.
- After fee omission, zero added service lines still return `CONFLICT` with the existing message **Configure a consultation fee or add a service before settling this walk-in**. This check occurs in quote and inside the create transaction. A rejected create rolls back the appointment, token, Charges, invoice, Payments, Receipts, and journal writes and emits no success audit. A successful omitted-fee create emits the same existing `opd.walk_in.create`, `invoice.issue`, and payment audits at the same post-commit boundary as a normal walk-in. See D017.

### List state and OPD day mechanics

- `apps/web/src/routes/$orgSlug/opd/index.tsx` adds `includeClosed: z.boolean().optional().catch(undefined)` to `opdDaySearchSchema`. `loaderDeps`, prefetch, date navigation, and the checkbox consume it. False removes the parameter. `q` is never route search.
- The day exposes one action labelled **New appointment**. It passes optional `patientId` and `includeClosed` to `/opd/new`; it never passes a timing discriminator. Slice 4 owns the day-side action and route schema. Slice 3 owns `/opd/new` validation, **Back**, and direct record navigation after success.
- `OpdSearchInput` remains client-local. Reload, Back, Cancel from intake, and a shared URL do not restore its text.

### Command ownership

`packages/db/package.json` owns the direct `drizzle-kit generate` script. The root `bun run db:generate` command is only a Turbo wrapper and is not a verified argument-forwarding form. Migration generation therefore runs with an explicit package working directory: `(cd packages/db && bun run db:generate -- --name=patient-dob-estimate-add)`, `(cd packages/db && bun run db:generate -- --custom --name=patient-dob-backfill)`, and `(cd packages/db && bun run db:generate -- --name=patient-dob-model-finalize)`. Slice-local automated verification uses only direct commands of the form `bun test --max-concurrency 1 --timeout 15000 <files>`. Slices do not run the root type or test gates. After the coordinator integrates all slices and resolves shared files, the coordinator runs `bun run check-types` once and `bun run test` once, in that order.

## Out of Scope

- Duplicate-merge tooling.
- A command palette.
- List virtualization.
- A merged booking-and-settlement procedure. `opd.book` and `opd.createWalkIn` keep the D015 boundary.
- Changes to consultation or follow-up fee configuration or selection precedence. The existing tenant-scoped selection still chooses the fee before the omission policy applies.
- A new route, appointment kind, pricing table, or procedure workflow for immediate attendance-fee omission.
- Attendance-fee omission during scheduled appointment check-in. The current check-in path keeps the configured fee.
- IPD.
- Multi-stop token journeys.
- WebSockets.
- Reports.

## Explicitly Deferred

- Screen-reader announcement for blank loading regions. This omission is already accepted elsewhere.
- Practitioner lanes.
- A stale-row marker during patients-list debounce.
- Scheduled/check-in attendance-fee omission. It needs a separate spec for a durable check-in pricing claim, authoritative quote or equivalent, transaction revalidation, and invoice-note persistence before that path can offer omission.
